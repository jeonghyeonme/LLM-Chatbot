# 🛠️ TroubleShooting: 크롤러 및 DB 연동 개발 로그

본 문서는 인하공업전문대학(INHATC) 데이터 수집 크롤러 및 Supabase DB 연동 과정에서 발생한 기술적 난제와 해결 과정을 기록합니다.

## 1. 식단표 데이터 수집 (Meal Crawler)

### ❌ 문제 상황
- **동적 로딩(CSR)**: 초기 타겟 URL(`subview.do`)은 껍데기 HTML만 제공하며, 실제 식단 데이터는 자바스크립트 실행 후 AJAX를 통해 호출됨.
- **보안 장벽**: `requests` 라이브러리로 직접 API(`getHaksaFoodMenuList.do`)를 호출했으나, 서버 측에서 세션/쿠키/봇 탐지 로직을 통해 `[]`(빈 배열)만 반환함.
- **데이터 부재**: 특정 기간(주말, 방학 등)에는 서버 데이터베이스 자체에 식단이 등록되지 않아 기술적 성공과 데이터 존재 여부를 구분하기 어려웠음.

### ✅ 해결 방법
- **Playwright 도입**: 단순 HTTP 요청 대신 실제 브라우저 엔진을 제어하는 Playwright를 도입.
- **사용자 행동 시뮬레이션**: 브라우저를 띄워 페이지에 접속한 후, '학생식당' 및 '교직원식당' 버튼을 **실제로 클릭**하여 자바스크립트 렌더링을 유도함.
- **DOM 파싱**: 브라우저 화면에 최종적으로 나타난 HTML 요소를 직접 파싱하여 보안 토큰이나 복잡한 API 규격 문제를 원천적으로 해결.

## 2. 학사일정 데이터 수집 (Schedule Crawler)

### ❌ 문제 상황
- **비정형 구조**: 학교 홈페이지가 반응형으로 개편되면서, 표준적인 `<table>` 구조가 아닌 `div > ul > li` 형태의 리스트 구조를 사용하여 기존 테이블 기반 파서가 작동하지 않음.
- **날짜 파싱**: `02.09. (월) ~ 02.12. (목)`와 같이 공백과 특수문자가 섞인 복잡한 날짜 형식을 표준 `DATE` 타입으로 변환하는 데 어려움이 있었음.

### ✅ 해결 방법
- **선택자 최적화**: `.yearSchdulWrap` 및 `ul.schdulList`를 타겟팅하여 유연하게 데이터를 추출하도록 로직 변경.
- **정규표현식 강화**: `(\d{1,2})\s*\.\s*(\d{1,2})` 패턴을 사용하여 다양한 날짜 표기 형식을 정확히 필터링하고 연도를 조합하여 `YYYY-MM-DD` 형식으로 정규화함.

## 3. Supabase DB 연동 및 환경 설정

### ❌ 문제 상황
- **권한 거부 (RLS)**: 보안을 위해 Row Level Security를 활성화했으나, 크롤러가 `anon` 키를 사용하여 데이터 저장이 차단됨.
- **설정 인식 실패**: `backend/core/config.py`에서 `.env` 파일을 읽어올 때, 실행 위치에 따라 상대 경로를 찾지 못해 Supabase URL/KEY가 누락되는 현상 발생.

### ✅ 해결 방법
- **service_role 키 사용**: RLS 보안을 우회하여 쓰기 권한을 가진 `service_role` 키를 `.env`에 적용.
- **절대 경로 로딩**: `os.path.abspath(__file__)`를 활용하여 실행 위치와 상관없이 `backend/.env` 파일을 정확히 찾아 로드하도록 `config.py` 로직을 견고하게 수정.

## 📝 유지보수 가이드
1. **데이터 수집 실패 시**: 학교 홈페이지에서 클래스명(`.yearSchdulWrap`)이나 식단 버튼의 텍스트가 변경되었는지 확인하십시오.
2. **브라우저 엔진**: 새로운 환경에서 실행할 경우 반드시 `python -m playwright install chromium` 명령어로 브라우저 엔진을 설치해야 합니다.
3. **보안 정책**: Supabase 테이블의 `UNIQUE` 제약 조건이 `upsert` 로직의 기준이 되므로, 스키마 변경 시 주의가 필요합니다.
