# 인하덕(Inha-Duck) 프로젝트 최종 발표 구성안

## 1. 개요
본 문서는 논문 "마스코트 기반 인터페이스와 서버리스 아키텍처를 활용한 대학 신입생 지원 지능형 챗봇 설계 및 구현"을 바탕으로 한 최종 발표 프레젠테이션 구성안입니다.

## 2. 슬라이드별 세부 구성

### Slide 1: 타이틀 (Title)
* **메인 제목:** 마스코트 기반 인터페이스와 서버리스 아키텍처를 활용한 대학 신입생 지원 지능형 챗봇: 인하덕
* **부제:** Design and Implementation of Mascot-Driven Intelligent Chatbot for Freshmen
* **핵심 요소:** 인덕이 마스코트 캐릭터 이미지, 대화형 UI 스크린샷

### Slide 2: 목차 (Contents)
* **Part 1. 프로젝트 개요 (Project Overview)**
  - 연구 배경 및 목적
  - 기존 정보 접근의 문제점 및 해결 방향
* **Part 2. 기술 설계 및 아키텍처 (System Architecture)**
  - 제로 코스트 서버리스 기술 스택
  - 성능 최적화를 위한 하이브리드 데이터 흐름
* **Part 3. 주요 구현 기능 (Key Features)**
  - 마스코트 기반 인터랙션 및 실시간 스트리밍(SSE)
  - RAG 기반 지능형 학사 지식 검색
  - 동적 캠퍼스 맵 및 가이드 시스템
* **Part 4. 데이터 자동화 및 성능 (Operations)**
  - 자동화된 데이터 수집 파이프라인 (Playwright)
  - 서버리스 환경에서의 효율적 리소스 관리 전략
* **Part 5. 결론 및 향후 계획 (Conclusion)**
  - 연구 성과 요약 및 고도화 방안

### Slide 3: 연구 배경 및 목적 (Background & Objectives)
* **현황 및 문제점:**
    * 정보의 파편화: 학사일정, 식단, 공지사항이 여러 채널에 분산됨
    * 접근성 저하: 복잡한 웹 UI로 인해 신입생들의 정보 획득 장벽 존재
    * 비용 및 유지보수: 기존 챗봇의 고비용 인프라 관리 및 유지 부담
* **연구 목적:**
    * 마스코트 페르소나를 통한 친숙한 UX 제공
    * 서버리스 기술을 활용한 운영 비용 제로화 실현

### Slide 4: 시스템 아키텍처 (System Architecture)
* **Stack:** React 19 + FastAPI + Supabase + Gemini 1.5 Flash
* **Deployment:** Vercel (Frontend & Serverless Functions)
* **특징:** 물리적 서버 관리 부담이 없는 **완전 서버리스(Full-Serverless)** 환경 구축

### Slide 5: 핵심 기능 1 - 마스코트 기반 인터랙션 UI
* **페르소나 설계:** 학교 선배 느낌의 친근한 말투(System Prompt)
* **응답 가속화:** SSE(Server-Sent Events) 스트리밍 적용
* **UX 최적화:** 20ms 타이핑 시뮬레이션으로 지루함 방지 및 퀵 메뉴 버튼 제공

### Slide 6: 핵심 기능 2 - 하이브리드 데이터 조회 전략
* **Technical Highlight:**
    * **Direct Access:** 식단, 일정 등 정적 데이터는 Supabase SDK로 직접 조회 (응답 속도 0.1s 내외)
    * **AI Query:** 복잡한 자연어 질문에만 백엔드 서버리스 함수 개입
* **효과:** 불필요한 연산 자원 소모 방지 및 응답 속도 극대화

### Slide 7: 핵심 기능 3 - RAG 기반 지능형 지식 검색
* **RAG 파이프라인:**
    * 수천 개의 공지사항을 벡터화하여 Supabase pgvector에 저장
    * 사용자 질문과 가장 유사한 문서 조각(Chunk)을 추출하여 LLM 컨텍스트로 제공
* **결과:** 학사 규정 및 최신 공지에 대한 할루시네이션(환각) 없는 정확한 답변

### Slide 8: 핵심 기능 4 - 동적 캠퍼스 가이드 시스템
* **지도 인터페이스:** 네이버 지도 API(react-naver-maps) 연동
* **상호작용:** 
    * 챗봇이 위치 안내 시 해당 좌표로 지도 자동 이동(panTo)
    * 강의실, 식당, 편의시설 마커 시각화

### Slide 9: 데이터 수집 및 관리 자동화
* **Web Crawling:** Playwright를 이용한 학내 사이트 동적 크롤링
* **Data Pre-processing:** HTML을 마크다운으로 변환하여 토큰 효율 극대화
* **자동화:** 주기적인 데이터 업데이트로 정보의 최신성 보장

### Slide 10: 결론 및 향후 과제
* **요약:** 서버리스와 하이브리드 전략을 통한 비용 효율적 대학 지원 시스템 구축 성공
* **향후 계획:**
    * 학과별 세부 데이터 확충
    * 사용자 피드백 기반 Gemini 모델 파인튜닝
    * 대학 전체 차원의 종합 정보 플랫폼으로 고도화
